## 主要兼容决策

| 范围          | 最终处理                                                                                                                                                                                                                   |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 身份和管理员  | 保留组织成员状态、目录来源、独立目录可见范围、部门/访问组、会话版本。管理员读取统一经过有效权限判断；持有孤立 grant 不代表有权访问。                                                                                       |

| 会话撤回      | 保留 Portal 会话版本和旧 IM 密文根密钥；remembered-session 全局退出按规范撤回记住的浏览器凭据，不宣称能凭空即时撤销所有无状态 Portal Cookie。                                                                              |
| 模型          | 保留限定供应商模型 ID、同名跨供应商模型、供应商协议和密钥、组织及成员治理。吸收模型发现/验证、元数据、fast mode、运行时选择和队列能力。失效的存储选择仍能显示与修复；执行入口继续验证当前可用性。                          |
| Skill         | 保留独立 Skill ACL，不把开放共享解释为私有技能自动授权。下一轮撤权会移除已物化资源；保留同名 archived 历史，active 同名仍拒绝。导入继续保留二进制、文本和文件路径约束。                                                    |
| Skill 执行位  | 批量和逐文件写入后统一设置 644/755；权限完成后才写 tree marker。缓存版本升级和 bundle 执行位变化均会触发重写；chmod 失败不标记完成。                                                                                       |
| 多 Skill 导入 | 使用现有组织事务一次提交 Skill、ACL、revision 和审计，代替逐项公开发布再补偿。所有名称检查在事务锁内重做，不引入通用 journal 系统。PG 事务提交前崩溃没有可见半成品；响应丢失后重试可能返回名称冲突，不承诺返回原成功响应。 |

| 初始化失败    | 同步构造失败不迁移部分数据库；MCP/目录初始化及定时清理不得抢跑。初始化失败不通过持久化审计触发局部建表；等待初始化期间可以关闭 MCP。                                                                                       |
| 跨 schema     | 不改已执行迁移的 checksum；增加目录存储前置/后置兼容迁移，按实际关系判断字段，避免另一 schema 的同名表使本 schema 漏列。                                                                                                   |
| 沙箱及网络    | 保留下游本地 Docker、持久 home、网络恢复、受控出口和私网例外；吸收上游适用的生命周期、工作目录和后端能力。不会把原生 IMAP/UDP 描述为 HTTP 代理已经支持的协议。                                                             |
| 运行与交付    | 合并运行恢复、排队、Worklog、webhook、会话 pin 等能力；排空保护更新串行化，停止时不会被迟到的异步 sweep 重新打开。                                                                                                         |

- 切换前保存 PG 自定义格式备份和旧镜像回退标签；备份仅保存在本机权限受限目录。
- 将切换前备份恢复到独立测试数据库。候选迁移前后，原有 124 张表的记录数无变化；候选新增后共 162 张表，第二次启动仍无重复写入；新增跨 schema 纠正迁移后再启动，只有迁移账本增加两行，原业务表数量不变。此证据证明记录数量保持，不等同于所有业务数据逐字节相等。
- 原有供应商配置可读取；使用现有已配置供应商实际完成一轮调用，持久会话记录中 assistant 精确回复 `QM_UPSTREAM_V011_OK`。测试未要求工具调用或向 IM/邮箱投递。

## 独立复审与仍需人工/环境证据的范围

本轮审查代理均未编写业务实现。`review_startup` 复核启动与 PG 边界及 Skill 原子导入设计/实现；`review_identity` 复核外部身份、有效管理员、补偿审计和退出契约。最终聚焦复审均无遗留阻塞；目录纠正迁移另经启动审查者复核。发现及处理：

| 发现                                 | 处理/回归                                                                    |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| MCP 构造阶段提前访问 PG              | 统一初始化屏障，显式/定时/变更触发均等待；拒绝及关闭路径回归。               |
| worker 忽略部署层初始化失败          | 启动前等待 `deploymentLayerReady`；失败时不初始化 sandbox、不启动任务处理。  |
| 只改 bundle 执行位未使缓存失效       | bundle hash 纳入执行位；仅改变 bundle 的双向 chmod 回归。                    |
| 外部成员资料邮箱能创建不可用的新邀请 | 非原始邀请邮箱返回冲突，不新增外部成员、grant 或发信；保留原始邮箱登录能力。 |

以下项目保持明确未签收，不能在 PR/发布说明中写成已完成：企业微信手机扫码与跨浏览器登录、测试 Bot 真实入站/出站和断线 lease 接管、所有已配置 IM 类型的外部平台故障注入、真实私网/UDP/已有 CONNECT 撤权演练、生产冻结窗口和新写入增量回滚。代码级消费者与失败路径测试不替代这些外部系统验收。

新增云后端、个人订阅登录、独立记忆服务、新服务合并拓扑、沙箱永久资源等能力按各自配置和验收门槛启用；本次本地 Compose 保留原拓扑与本地 Docker。没有为了展示上游功能修改用户的组织策略、替换供应商或打开新后端。

PR 和 CI 是代码集成门槛；本地真实调用通过不代表生产发布已获批准。main 合并及生产发布保持独立操作。
