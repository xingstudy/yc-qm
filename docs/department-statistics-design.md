# 部门统计改进设计

状态：设计已确认，进入实现与验证。

## 改进前的行为与既有约定

- 组织成员可以加入多个部门；加入部门与指定主部门是两个独立操作。
- 用量发生时只读取显式主部门。用户仅加入一个部门而没有主部门标记时，仍记录为“未分配”。
- 用量保存部门及其祖先的发生时快照。父部门筛选可包含子部门，但当前部门分组和选择器主要按平铺列表展示。
- 当前规则要求历史归属保持稳定，不随人员调动或组织调整变化。参见[现有术语](../GLOSSARY.md)、[永久保留与历史归属决策](adr/0001-preserve-usage-and-historical-attribution.md)。
- 用户已明确授权一次按当前手工指定主部门回填原先未分配用量。该操作是明确请求的历史更正，不等同于允许日常查询静默重分历史。

## 已确认决策

用户于 2026-11-06 确认全部 D1–D9 建议。

### D1：默认归属规则

有效的显式主部门优先。没有主部门但只有一个有效部门时，使用量自动采用该部门；多个有效部门且没有主部门时显示“归属待确认”；没有部门时显示“未分配”。每条消耗只归属一次，保留用户加入多个部门的能力。

本规则只确定用量归属，不自动修改组织主部门标记，具体边界见 D4。选择规则见[单部门自动归属决策](adr/0004-single-department-usage-attribution.md)。

### D2：保持历史稳定

默认采用发生时部门及其组织层级快照。人员调动、部门移动或重命名不自动重分历史。缺失或错误的归属通过明确的预览、更正和审计流程处理，保留更正前信息及依据。

此前按当前主部门回填原先未分配记录，是用户明确授权的一次更正，不作为后台静默重分历史的先例。

### D3：组织树与统计一致性

部门统计采用可展开组织树，父部门默认展示其直属及全部下级合计，并可查看直属用量。父子行是包含关系，组织总计从明细独立去重计算。筛选、趋势及导出沿用同一归属和汇总口径。

### D4：自动归属不修改组织关系

仅为用量选择并保存归属，不自动修改用户的主部门标记。成员管理中显式指定的主部门仍有优先级；自动选择的依据可在用量明细中追溯。

### D5：历史更正的操作边界

由组织管理员执行预览后确认，默认只选择未分配且用户身份明确的记录。已有部门但确实错误的记录必须单独选择，并在预览中显示原归属、目标归属和覆盖数量，不能因用户换部门而批量覆盖全部历史。

缺少用户身份的迁移记录不依赖当前会话成员或项目成员推测归属；已知的用户可采用管理员明确选择的主部门或唯一有效部门作为更正依据。

### D6：历史范围跨越部门移动

例如研发组上半月属于产品部、下半月移入技术部。按明细中的发生时路径分别展示在两条历史分支下，并标识不同历史路径。每条明细只进入实际对应的分支，研发组整体筛选仍覆盖两段数据，不把旧数据搬到当前父部门。

### D7：有效组织节点的范围

现有组织模型包括部门、团队和组织根节点，团队已经可以成为主部门。统计继续支持有效的部门和团队，组织根节点只用于汇总，不参与自动归属；归档节点不用于新用量的自动选择，但其历史用量仍保留。

## 既有指标约束

- 父部门活跃用户数按用户去重，不能直接相加各子部门的活跃用户数；跨天、跨部门出现的同一用户在整个查询范围只计一次。
- 子树费用和 Token 需要连同计量覆盖率一起汇总。未知金额不当成明确为零；部分已知时展示已知合计与不完整状态。
- 自动任务沿用任务责任人，系统辅助处理优先继承父任务的归属。没有可靠用户身份的系统记录保留未分配，不从 Project 成员推测归属。
- 请求重试保留首次归属，后台更正与投影需要支持事务、幂等、多实例和失败重试。

## 补充决策

### D8：零用量部门

默认只展示所选范围内有使用量的部门、团队及其必要祖先，提供“显示空部门”开关。开启时补充当前有效组织节点；没有计量记录的节点明确作为零用量展示，不将有调用但计量未知的节点当成空部门。

当前组织关系仅用于补充零用量节点，不用于移动、重命名或覆盖历史路径上的已有用量分支。历史归档节点只要在查询范围内有用量仍展示。

### D9：无法归属的记录如何计入组织树

将“未分配”“归属待确认”“历史归属未知”作为组织总计下的独立汇总项，显示原因并能筛出对应明细。它们的消耗仍计入组织总量，不挂到任意实际部门。

旧记录未保存归属原因时，明确标记历史原因未记录，不根据当前关系反推其发生时的歧义状态。可由 D5 的明确更正流程处理。

## 实施范围

- 在共用的用量归属选择处实现 D1、D4、D7，保留发生时快照与重试身份，覆盖人工请求、自动任务及系统辅助处理的调用方。
- 部门统计接口及页面提供历史路径组织树、直属/子树用量、独立组织总计；部门筛选、趋势、明细与导出使用相同范围。
- 新增组织管理员历史归属更正预览与确认入口，覆盖未分配及显式选择的错误归属。持久保存更正依据、修改前归属与审计，既有 Token 和费用不变。
- 预览与确认绑定组织和操作者，确认前重新校验权限、预览有效期、目标部门有效性、候选记录及当前组织关系版本。过期或发生变化时要求重新预览。
- 确认采用事务及幂等处理；提交后标记待投影，通过现有减旧桶/加新桶机制更新汇总。协调投影与批量更正的锁顺序，避免多实例并发冲突。
- 首次计量前缺少主部门且用户只有一个有效部门时不需要额外操作。已经更正的生产历史不因本次代码上线自动重复重写。

## 验收范围

- 主部门优先、唯一部门自动归属、多部门歧义、无部门、组织根排除、团队纳入及归档节点历史保留。
- 部门移动、重命名和用户调动前后保持原快照；历史分支可区分，筛选同一部门可覆盖它的不同历史分支。
- 单用户跨天/跨部门去重、父子树费用与 Token 汇总、已知与未知混合时的覆盖率，组织总计与明细一致。
- 组织管理员与部门负责人权限隔离、跨组织/跨操作者、预览过期/过时、目标归档、事务失败、幂等重试、并发投影及更正审计。
- 部门树、直属/子树切换、筛选、趋势、明细、更正入口与 CSV 导出的页面验证；只运行受影响测试、拥有项目的类型检查和变更文件格式/静态检查。

全部设计决定已确认，以上范围用于实现和验收。

## 操作与数据边界

管理后台“使用量”中的部门维度展示组织树。“部门统计口径”同时作用于部门筛选、趋势、明细及导出；汇总 CSV 以独立列区分直属和含下级数据，并保存分支 ID、历史路径名称和 ID，避免重命名后的同 ID 分支混淆。

“历史部门归属更正”使用独立日期范围，可限制用户和记录。目标部门留空时采用当前主部门或唯一有效部门，也可明确指定一个有效部门。覆盖已有归属必须提供具体记录 ID；更正原因必填。预览最多选择 10000 条记录，界面展示前 100 条变更及完整数量，确认时处理全部候选记录。

新增账本迁移只创建预览表 `usage_department_previews` 和更正审计表 `usage_department_changes`，不执行历史回填。审计与更正处于同一事务，永久保存更正前后快照、选择依据、原因和操作者。归属依据不加入现有汇总桶键，确保旧投影仍可按原键扣减；重试继续保留首次归属或已确认的更正结果。
