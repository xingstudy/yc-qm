# 使用量 Dashboard 展示改版

状态：2026-10-14 用户确认其余推荐方案；展示、参考定价与历史未知费用补估已实现并接入 WSL QA 环境。

本次改版基于[已确认需求](usage-dashboard-prd.md)与[现有实现](usage-dashboard-design.md)，保留永久存储、发生时归属、北京时间、自定义日期和独立汇总粒度等口径。

## 用户明确提出的改进

- 用户、Project、部门、模型等条件提供“全部”和下拉选择，减少当前展开列表的占用。
- 报表展示可视化趋势，而非只展示数字表格。
- 两份 Codex LB 参考 PDF 仅用于借鉴展示方式，最终设计适应 qm 的指标、组织归属和数据覆盖情况。

## 初版改版前的页面与数据事实

- 用户、Project、部门、模型、来源、授权使用原生三行多选列表，没有搜索与显式的“全部”显示。日期范围、粒度和排行维度已有单选。
- 当前趋势是周期数据表；同一报表接口已有各周期的请求、活跃用户、调用、Token、参考费用和覆盖计数，可用于绘图。
- 当前 facets 来自历史用量汇总，每维最多 1,000 项，未包含全部当前目录中的零使用对象。部门还包含发生时祖先；已离职、已删除、未分配和历史归属未知对象有独立身份。
- 空字符串是“无 Project”或“未分配”的合法 ID，不能用它同时表示“全部”。全部应表达为不施加该维度限制。
- 趋势接口仅返回有汇总记录的周期，没有自动填补日期。最早记录之前、已知计量缺口与确认零使用不能混为一类。
- 完全未知的 Token 或费用应显示未知；部分已知显示已知合计及该周期覆盖率。组织级未完整计量数量不能充当当前筛选下的费用覆盖率。
- 当前排行按调用数、请求数排序，最多 200 项。准确切换 Token、费用等指标排行需要服务端排序，不能仅重排已截断的 200 项。
- 当前管理后台没有完整图表库；原生 SVG 与现有 CSP 兼容，可减少依赖。图表需要可访问说明、键盘可用交互及对应数据表。
- 首 Token 时间、队列等待和 Token 吞吐速率不是现有 Usage 指标，参考图中的这些指标不直接迁入本次报表。

## 已确认交互

### Q1：下拉筛选

推荐用户、Project、部门、模型、来源、授权均使用可搜索的多选下拉，默认显示“全部”；单项显示名称，多项显示选中数量。支持移除单个条件和清空恢复全部。各维度筛选口径沿用已确认的并集／交集规则。

### Q2：总览与趋势

推荐页面先展示活跃用户、用户请求、已知模型调用、已知 Token、已知参考费用卡片及上期变化。下方默认展示请求与模型调用趋势、Token 趋势，支持切换活跃用户与参考费用，并保留可展开的周期数据表。

时间范围与日／周／月汇总粒度独立选择。趋势横轴按真实时间排列，不完整的自然周／月标记实际覆盖范围。未知点不能当作零点连接。

### Q3：维度报表

推荐通过用户、Project、部门、模型标签切换分组，用横向 Top N 条形排行配合详细表格；可选择请求、模型调用、Token、参考费用作为排行指标。服务端按所选指标排序，注明展示范围，不把被截断的排行解释为完整分布。

点击对象可下钻到筛选，顶部显示可移除的条件。总览、趋势、排行、明细和 CSV 使用同一组筛选条件。切换排行维度本身不增加筛选条件。

### Q4：参考费用

推荐继续展示已知参考费用与费用覆盖率，不作为默认排行指标。完全未知周期显示缺口，部分已知周期标记不完整；不因历史费用缺失将其显示成免费。

用户进一步提出：参考各厂家的官方 API 定价提供默认单价，允许管理员修改 Token 单价，以应对官方价格变更。Q4a–Q4c 已于 2026-10-14 确认，以下定价规则已接受并实现。Q1–Q3 的展示交互也已接受。

### Q4a：估算与结算的边界

已确认本次仅用于参考成本分析，不新增内部结算或用户扣费。提供官方默认价格与管理员覆盖价格，保留可靠 SDK 返回金额及其来源；由价格表推算的金额标记为估算。订阅使用可以展示 API 等价参考估算，但不解释为额外付款。

配置按供应商、实际模型及适用服务类型匹配，避免将代理模型别名直接当作官方模型。输入、输出、缓存读取、缓存写入分别定价，统一以 USD／百万 Token 为基础单位；不支持或无法确认的类别不能默认视为免费。

供应商存在缓存有效期、长上下文和批处理等不同价格规则。需要记录适用条件，只在模型、计量字段及价格条件匹配时估算；缺少可靠信息仍保持未知，不能通过补充单价伪造缺失 Token。

### Q4b：价格生效与历史

已确认保存价格版本、来源、核对日期、生效时间及修改记录。改价默认仅影响生效后的使用量，已记录历史费用保持原口径；历史补估和纠错通过独立预览确认执行，不在管理员保存新价格时静默重算过去报表。

### Q4c：默认价格更新

已确认首版随系统更新维护官方默认价格，管理员可手动更新、查看来源和核对日期、恢复默认。更新默认价格不覆盖管理员自定义价格；默认价更新与恢复默认仍遵守价格版本和生效时间规则。

自动发现官方变更、展示差异和确认同步属于另一项能力，不能将当前包内价格表描述成实时同步官方价格。

### 官方规则核对

2026-10-14 查看了 [OpenAI API 定价](https://developers.openai.com/api/docs/pricing)与 [Claude API 定价](https://platform.claude.com/docs/en/about-claude/pricing)。定价规则包含不同 Token 类别及服务条件；本文不固化具体金额，实施时需核对实际使用模型和适用价格档位。

### 定价实现约束

现有管理后台已支持部分新增模型的四项单价及上下文档位，但不能修改所有已有模型，也没有价格生效版本。应建立独立参考价格配置，复用单价校验、组织管理员权限、Postgres 持久化和审计模式；仅调整参考价格不应触发模型连接验证或改变模型启用状态。

可靠 SDK 金额需要保留；当前 Pi 的目录价格估算、Codex 的未知金额以及 OpenCode 缺失金额转零的行为需在共享计量层统一处理。估算应按实际调用的 Token 类别、服务条件与价格版本完成，而非在图表中用聚合 Token 乘当前单价。

现有永久事实未保存一小时缓存写入、快速模式或价格版本等信息。新估算需要持久化足够的适用条件和价格依据；历史缺失这些条件时，不得承诺能精确回算。配置中的“未配置单价”与明确设置为零的单价需要分别表达。

价格历史取舍见[参考定价版本与历史费用决策](adr/0003-version-reference-prices.md)。

## 补充交互口径

下拉合并当前目录中的零使用对象与历史对象，显示失效对象状态；部门筛选包含发生时子部门。默认两张趋势图各自切换指标，上期通过总览变化和可展开报表展示，周期数据表也可展开。排行默认按已知 Token，Top 10 条形图与最多 200 项表格配套，支持服务端切换排序和下钻。

最终交互已确认；实施后执行针对性测试和实际 QA 环境的视觉验收。

## 历史未知费用补估

2026-10-14 用户确认新模型补充价格后的历史补估方式：选定历史记录模型、日期范围及价格版本，先预览再确认。预览不改变账本，区分可补估、已有金额、未完成、模型身份不明确或不匹配、服务条件未知及 Token／单价不足的记录。仅成本未知且条件明确的记录可补估；Token、归属、已有 SDK 金额与历史估算保持原值。

补估可显式使用选定价格版本估算其生效前的未知费用，不改变价格版本对新调用的生效规则。预览固定当时记录集合与价格快照，15 分钟有效，单次最多 10000 条未知费用记录。Postgres 事务确认时锁定记录并检查是否变化；变化则要求重新预览，重试确认保持幂等，失败回滚全部改动。原费用状态、价格快照、操作者及确认时间永久保留，日汇总通过既有增量机制更新；费用趋势和覆盖率随后反映补估结果。

在新增身份字段之前产生的历史记录，可能没有可靠供应商、实际模型或服务条件。当前模型目录不能证明其发生时的路由，因此这些记录仍显示未知；首版不提供猜测模型映射或凭当前配置自动回写历史的功能。已知费用纠错或按不同价格重估不包含在本次补估入口中。

## 可组合个人看板与折叠筛选

2026-10-14 用户要求进一步压缩筛选占用，详细借鉴两份 PDF，并采用 Grafana 的可组合面板思想；个人布局保存到数据库已确认。

重新逐页查看 `Codex LB.pdf` 的 4 页：第 1 页使用紧凑工具栏、指标卡和按日费用图，第 2 页以多个独立面板展示 Token 和性能趋势，第 3 页将模型分布、来源分布与可导出明细并列，第 4 页延续明细。`Codex LB2.pdf` 的 4 页由总览、对象排行与搜索列表进入对象详情，第 3 页将单个对象的费用分布和时间趋势组合在同一详情卡片。参考资料中的首 Token 时间、吞吐、队列等待及 API Key 状态没有可靠的当前 Usage 数据，因此不移植这些指标或示例数值。

参考 [Grafana 的面板布局](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/create-dashboard/)和[全局变量](https://grafana.com/docs/grafana/latest/visualizations/dashboards/variables/)，采用共享日期和筛选、独立维度与指标、可组合排列的个人面板。页面使用已有管理后台组件及 SVG，保留 qm 的权限、历史归属和覆盖率口径。

- 默认折叠筛选区，收起时显示选中数量；已选条件在顶部保留可移除标签。展开后仍能搜索、多选、清空为全部。默认日期预设隐藏自定义日期输入，仅自定义范围显示起止日期。
- 默认 6 个面板：总览 Token、用户 Token、Project Token、部门 Token、模型 Token、总览参考费用；各维度是真实多对象时间曲线。
- 面板可选择总览、用户、Project、部门、模型、任务来源或授权，以及 Token、参考费用、调用、请求、活跃用户。支持折线趋势、面积趋势和维度横向排行；总览使用时间趋势。
- 最多组合 8 个面板；可添加、移除、上下移动、选择半行／整行，窄区域自动改为一列。面板设置默认折叠，避免配置控件再次占据图表空间。
- 同一面板按选定范围与指标选择前 5 个对象，整个时间范围内保持同一对象身份；不会按日重新选 Top N 并把不同对象拼成同一条线。前 5 项不代表完整分布，页面保留完整排行入口。
- 所有面板继承顶部日期、粒度与组合筛选。不存在或计量未知的点保留缺口，部分已知值通过工具提示展示覆盖情况，首尾非完整自然周／月明确标记。
- 个人布局通过显式“保存个人布局”写入既有 Postgres UI 状态存储，按组织和管理员隔离；日期和筛选仍由 URL 表达。布局保存包含版本检查，其他页面已经修改时拒绝覆盖并提示重新加载；存储不可用时不会误报保存成功。
- 维度趋势批量请求、相同维度／指标去重，按需查询日汇总与最多 5 个对象，避免扫描原始使用量事实或为每个点单独发请求。现有可见性和历史范围刷新策略保持不变。
